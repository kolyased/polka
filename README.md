# Полка

Личная библиотека аудиокниг с веб-плеером: общий прогресс для нескольких файлов, оглавление, закладки, скорость, таймер сна и скачивание для офлайн-прослушивания. Один владелец, Node.js 24+, SQLite, без npm-зависимостей.

## Локальный запуск

```sh
npm start
```

Откройте http://localhost:8787. При первом запуске возьмите одноразовый ключ из `data/setup-key.txt` и создайте пароль от 12 символов. После настройки ключ удаляется. Пароль хранится только как scrypt-хеш; восстановить его из базы нельзя.

```sh
npm test
npm run import -- /absolute/path/to/audiobooks
```

Импорт рекурсивно обходит каталог: каждая папка с MP3/M4A/M4B становится книгой, файлы упорядочиваются по номеру в названии. Поддерживается `cover.jpg/png/jpeg/webp`. Повторный импорт того же пути пропускается. Для анализа аудио на macOS используется `afinfo`, на Linux установите `ffmpeg` (с `ffprobe`). Встроенные главы извлекаются через ffprobe на Linux. Аудиокниги и пользовательские данные не входят в репозиторий и не покрываются лицензией проекта.

Через интерфейс можно загружать до 500 файлов частями с возобновлением. Максимум книги — 3 ГиБ, библиотеки по умолчанию — 10 ГиБ, резерв свободного диска — 2 ГиБ. Неактивные импорты удаляются через 7 суток при очередной операции импорта, проверке хранилища или ежечасной очистке работающего сервера. `DELETE /api/imports/:id` отменяет незавершённый импорт. Завершение сериализуется с загрузками; журнал в SQLite позволяет завершить публикацию после прерванного переноса каталога при перезапуске или следующем обслуживании импортов.

## Docker и HTTPS

```sh
cp .env.example .env
# Укажите свой ORIGIN в .env
docker compose --env-file .env -f deploy/compose.yml up -d --build
docker compose -f deploy/compose.yml exec polka cat /data/setup-key.txt
```

Порт 8787 публикуется только на loopback хоста. Для удалённого доступа настройте HTTPS reverse proxy, например Caddy по `deploy/Caddyfile.example`, и задайте `ORIGIN=https://ваш-домен`. Не передавайте пароль по незашифрованной сети. Контейнер работает от непривилегированного пользователя; данные находятся в постоянном томе `/data`.

`TRUSTED_PROXIES` по умолчанию пуст. Если приложение находится за прокси, укажите точные адреса непосредственного прокси, которые Node видит как `remoteAddress` (в Docker это может быть адрес шлюза). Прокси должен **перезаписывать** `X-Forwarded-For` единственным IP клиента. Цепочки адресов и заголовки от недоверенных соединений игнорируются. Закройте прямой доступ к приложению из внешней сети. При пустом списке лимит входа применяется по адресу соединения; клиенты одного прокси разделяют лимит.

Для фонового воспроизведения без переключения между частями:

```sh
docker compose -f deploy/compose.yml exec polka node scripts/continuous.mjs
```

Совместимые MP3 объединяются без перекодирования; остальные форматы переводятся в AAC/M4B. Перед обработкой проверяется запас диска для результата и 2 ГиБ резерва. Исходники сохраняются и учитываются в квоте. Тайм-аут обработки по умолчанию 6 часов; `CONTINUOUS_TIMEOUT_SECONDS` допускает 30–86400 секунд. При ошибке временный файл удаляется. Скрипт защищён каталогом `/data/continuous.lock`; после аварийного завершения процесса удаляйте его только убедившись, что другая обработка не запущена. После изменения аудио скачайте офлайн-копию заново.

## Данные и офлайн

`data/library.sqlite` содержит владельца, хеши сессий, каталог и прогресс. Аудиофайлы выдаются после авторизации с HTTP Range. Не редактируйте БД и аудиофайлы одновременно с работающими инструментами импорта. Делайте согласованные резервные копии всего тома при остановленном приложении или через SQLite backup API вместе с файлами. Копирование только SQLite без WAL при работающем сервере небезопасно. Проверяйте восстановление отдельно.

Офлайн-копии хранятся в Cache Storage и IndexedDB блоками по 4 МиБ, без шифрования. Версия файла учитывает его размер и временные метки файловой системы; при доступном сервере проверяется ETag. Для замены аудио используйте импорт нового файла, не сохраняйте искусственно прежние метаданные. Без сети невозможно обнаружить изменение на сервере. Старые копии без версии требуется скачать заново.

Выход проверяет синхронизацию позиций и закладок, останавливает загрузки, удаляет весь медиакэш и локальные данные, затем отзывает серверную сессию. При ошибке очистки выход показывает ошибку и допускает повторную попытку. Для отзыва сессии требуется сеть. Конфликты прогресса разрешаются в плеере. Закладки синхронизируются набором; слияние одновременных правок с разных устройств пока не реализовано.

Браузер может удалить офлайн-хранилище при нехватке места. Веб-таймер и фоновые загрузки зависят от ограничений ОС. Перед использованием на телефоне проверьте блокировку экрана, перемотку, офлайн-перезапуск и возврат сети.

## Разработка

`npm test` запускает тесты HTTP, импорта, плеера и офлайн-диапазонов. CI использует Node.js 24 и ffmpeg. Скриншоты `preview-*.png` иллюстрируют прежние версии интерфейса и содержат только названия книг и сведения плеера.
